# English Assist 英文输入

本项目是登记在 Windows 英语（美国）语言下的原生 TSF 输入法，提供离线英文补全、拼写建议、中文释义、词性、可选音标和拼音找英文。0.4.0增加词前空格、原串内部自动分词、Shift开关和浮动状态栏；正式构建、升级与真实应用的版本证据见 [验证记录](english-assist/INPUT_VALIDATION.md)。

历史 0.2 R5 在 2026-11-09 完成正式构建与升级，验证目录为 `C:\Program Files\EnglishAssist\versions\0.2.0-20261109035537-776110`。记事本进程39900的真实 AI 预览、应用及取消与保存文件一致；这些通过结果保留为该版本证据，不能用于宣称0.3已安装或已验收。旧文件实际重启删除及其他应用兼容性仍按验证记录区分。

## 0.4 自动空格与原串分词

下述核心输入规则已在0.4.0 R4正式安装版的冷启动记事本逐键检查，并读取保存后的自有文件核对；最终R5安装版又复验了连写Space、英文加拼音选词、原文Enter、Shift及状态栏拖动/隐藏恢复。最终产物和检查点见验证记录。有限记事本检查不等于所有应用兼容。

Windows 默认开启“自动词前空格”。分别确认 `i`、`am`、`robot` 时，仅在相邻英文需要分隔的位置补一个前置空格；从不自动加尾空格，光标紧贴 `robot`。已有空格、换行或开括号等边界不会再补一个空格，也不删除应用原有的空白。拼音查找后确认英文候选采用相同规则；中文释义、词性等展示内容不写入正文。

同时开启“连写智能分词”时，未明确选词的 Space 可将 `iamrobot` 确认为 `I am robot`，将 `iamrobotandilikeapples` 确认为 `I am robot and I like apples`；只在原串内部插入空格，不补出尚未输入的字母或词。完整已有词和个人词库词条保持完整，未知片段或歧义过大的串保留原样。该自动确认路径独立于预测候选列表；例如 `iamt` 不会因为候选中出现 `trying to` 而自动写成 `I am trying to`。内部原串分词最多处理64个ASCII字符、16个词，超出范围保留原串。

Tab、数字、点击或先明确选择候选再按 Space，仍可接受选中的补全；自动空格开启时按上述规则补前置空格，不附加尾空格。单按 Shift 只切换自动空格，不切换英语模式或关闭补词、拼音、连写等功能；Shift 组合键继续保留大写及应用快捷键含义。关闭自动空格后，有组字时 Space 确认原串或明确选中的候选并输入手动空格，数字、Tab、点击则不自动补前后空格。没有组字时，物理 Space 始终交给应用处理。

有组字时，Enter 在自动空格开/关、候选已选择/未选择、翻页后的状态下都原样上屏并吃键；不执行分词、不补前置或尾随空格、不插入换行，也不提交聊天或搜索。组字结束后的下一次 Enter 由应用正常处理；Ctrl+Enter 等带修饰键的应用快捷键保持原有行为。

浮动状态栏显示实时 CapsLock 大小写状态、自动空格和补词/拼音/连写开关，可打开设置、拖动或隐藏；设置中可重新显示并恢复默认位置。状态栏不得夺走编辑器焦点，开关操作不得提前提交或丢失正在输入的原串。密码、私密、只读或不确定的邻区不用于自动空格的周边文字读取。

## 0.3 连写输入（历史版本行为）

本地解码同时考虑整个单词前缀及多条分词路径，末尾可以是尚未完成的单词。例如 `ia` 保留 `ia…` 单词补全及 `I am` 等解释；`iamt` 可识别为 `I am` 加当前尾词 `t…`，候选行仅显示 `trying`、`trying to`，确认时完整提交 `I am trying`、`I am trying to` 一次，前缀不重复。

0.3.1候选顶部按当前选项显示推断词界，如 `I · a`、`I am · g`、`I am · t`，让已识别的前缀可见；候选主行仍只显示当前尾词。只有推断前缀与原始输入严格匹配时才显示该提示，普通单词或不匹配时保留原串；它不改写组合或提交文字。可靠多词前缀后增加有限词频回退，使缺少相邻词记录的gay、good仍能参与候选，单词前缀与无可靠前缀的噪声仍严格处理。冷启动记事本PID46068已确认加载本次DLL：iamg顶部为 `I am · g`、首项going；iamga按3、iamgood按Tab、iamt按4，保存文件精确得到三行 `I am gay`、`I am good`、`I am trying to`。排名仅为本次快照，不是保证；本地解码不是完整语法或神经语言模型句意理解，`imag` 与 `iamg` 字符不同，仍走普通单词路径。

推断的词界不会提前写到当前组合之外。未显式选词时，Esc 保留原始串，空格保留原始串并加空格；退格重新计算词界。超过48个输入字符后回到普通单词补全路径，不截断或自动改写原输入。短输入可能有多个合理解释，示例不保证唯一答案或固定候选位置。

Windows 0.3 在“输入与查词”默认开启“连写智能分词”和“短语候选”，可分别关闭。其他前端的共享Kernel默认关闭两项，须先支持显示候选后缀与完整正文分离再启用。私有RichEdit已验证iamt第4项trying to确认后完整提交一次，退格回iambic、拼音apple、Esc原串及翻页也通过；这不是本轮Notepad或全部应用实测。短语没有独立释义时显示“短语补全”，不借用单词词性/中文。

两个开关的off/on保存已在前一个0.3设置exe中核对HKCU；最终exe摘要不同，最终输入页只确认两项on并截图，没有重复保存测试，不能称全部控件已测。

## 选择输入法

按 Win+Space，选择 **English Assist 英文助手**。也可在“设置 → 时间和语言 → 语言和区域 → 英语（美国）→ 语言选项 → 键盘”检查入口。安装器保留其他键盘和原默认输入法。

升级后先保存工作，完全退出要使用的应用再重新打开，让它加载新版输入组件；只开新窗口可能仍复用旧进程。本次iamg截图已确认来自仍加载0.2 R5 DLL的记事本PID39900，不能代表已安装0.3的候选行为，也不是两个连写开关失效的证据。

## 候选与键盘（0.4）

以下键位对应0.4行为；0.3.x历史空格/回车规则见上节。

| 操作 | 行为 |
| --- | --- |
| 输入英文 | 离线补全；候选显示词性和中文释义，保留大小写 |
| 输入拼音 | 如 nihao、pingguo、xuexi，查找对应英文；可在设置中关闭 |
| 1–5 | 接受当前页对应候选；自动空格开启时按需补前置空格，从不加尾空格 |
| Tab / 点击候选 | 接受当前候选；自动空格开启时按需补前置空格，从不加尾空格 |
| - 或 _ | 上一页 |
| = 或 + | 下一页 |
| PageUp / PageDown | 上一页 / 下一页 |
| ↑ / ↓ | 明确选择候选 |
| 空格（自动空格开） | 确认原串；连写开启时仅分隔已输入词；明确选词时接受该候选；不加尾空格 |
| 空格（自动空格关） | 确认原串或明确选中的候选，并输入手动物理空格 |
| 有组字时 Enter | 始终原样上屏并吃键，不分词、不加空格、不换行或提交应用 |
| 无组字时 Space / Enter | 交给应用处理 |
| 单按 Shift | 只切换自动空格；Shift组合键保持原义 |
| Esc | 保留原输入并结束候选 |
| 无候选时数字、翻页符号、Tab | 保留应用原有输入行为 |
| Ctrl / Alt 快捷键及光标导航 | 结束当前原词，保留应用原有操作 |

每页最多五条。0、6–9 或当前页没有对应候选的数字不会选择隐藏项。输入 python3 等原始字符串时，如候选仍可见，可先按 Esc，再输入数字。

拼写建议不自动改写原词。候选上的中文、词性、音标和编号只用于展示，上屏文字只有英文。

## 设置与个人词库

设置按常规、输入与查词、候选外观、个人词库与数据、快捷键、AI 服务及关于分类。

可从开始菜单打开“英文助手设置”。在真正的 AppContainer 中，从候选菜单打开设置受限制；应用是打包形式不等于它一定运行在 AppContainer 中。

候选外观支持跟随系统/浅色/深色、字号、宽度、紧凑模式和词义字段显隐。偏好自动保存，回到输入框后生效。

个人词库提供显式增删改、搜索、导入和导出。JSON 或 UTF-8 TXT/TSV 可导入；TXT/TSV 每行为“单词<Tab>释义”。保存前保留上个版本 manual.json.bak，返回输入框时后台刷新。自动学习关闭，不记录输入历史来生成个人词条；输入不启动学习后台服务，也不添加该服务的登录启动项。

## AI 语法修正与补句

在设置中配置 DeepSeek 或兼容服务、模型和 API Key。密钥保存在 Windows 凭据管理器；本地补词和查词无需密钥或联网。

选中需要处理的英文文本后按 Ctrl+Alt+G，选择语法修正或补句。检查预览后按 Ctrl+Enter 应用，Esc 取消。文本、选区或文档焦点发生变化时，旧结果失效；失败时保留原文。首版需要明确选区，最多 2048 个 UTF-16 单元。

历史0.2 R5时，用户私下配置新凭据后通过真实 production HTTP 验证了语法修正和补句。该版真实记事本中，`She go to school every day.` 预览为 `She goes to school every day.`，Ctrl+Enter 应用后保存文件完全一致；补句既验证了 Esc 取消保留原文，也验证了确认替换后保存结果一致。具体样例、两次 HTTP 观察耗时及版本边界见验证记录；不能将少量样例当作普遍质量或延迟保证。

0.3升级后production CLI再次真实请求成功：语法样例返回 `She goes to school every day.`（702ms），补句返回 `I would like to know more about it.`（865ms）。这是本版CLI服务验证，未重新执行本轮Notepad AI GUI；少量观察耗时不等于端到端延迟保证。

0.4.0本轮没有重新调用AI服务或执行AI GUI；上述0.3 CLI与0.2 R5记事本AI结果保留历史版本边界，不作为0.4.0的新联机或AI界面实测。

在真正的 AppContainer 中，若 AI 辅助进程尚未运行，本版无法从该应用冷启动 AI。此限制不泛指所有打包应用；离线补全和查词无需 AI 辅助进程。

## 构建

需要 Rust MSVC、MSVC x64/x86、Windows SDK、Inno Setup 6 和 Python 3.11+；Python 无需第三方包，可通过 `-PythonPath` 或 `ENGLISH_ASSIST_PYTHON` 指定。

~~~powershell
.\platforms\windows\installer\build-english-assist.ps1 -Installer -PythonPath C:\Python313\python.exe
~~~

构建脚本生成、校验离线资源，编译 x64/x86 并运行回归测试，不自动安装或改键盘列表。源码及数据许可必须随交付保留。
