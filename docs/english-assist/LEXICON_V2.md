## 离线编译与词级排序

[编译器](../../tools/english-assist/build-lexicon.py) 在离线构建阶段处理原文，输入线程不解析 CSV、YAML 或 SQL。

1. 保留每条中文词项、原始数字声调读音、义项和来源；无声调拼音只作为查找键。
2. 从 CC-CEDICT 义项提取允许的英文词头；从 ECDICT 的**完整中文释义项**反向关联到已知中文词项，不做子串匹配或猜测中文分词。
3. 反向补充遇到多音词时，只采用原始英文义项能支持的读音；缺少佐证且读音有歧义时跳过。已有明确 lemma 的屈折词形不扩散反向关联，也不猜词根。原始 CC-CEDICT 的明确多音义项仍可保留。
4. 万象频率按“中文词项＋具体声调读音”匹配，不能把其他读音的高频搬过来。
5. 按现代／常用中文词项分组，先交错覆盖常用词项，再展开更多义项及低频、旧义、专名。英文词频只参与组内次级取舍，运行时不能再用全局英文词频覆盖这一顺序。

例如 `xiang` 的不同同音词应保留“想／向／香／襄／庠”等证据，而不是把所有英文释义混成只按 `to`、`help` 等英文高频词排序的集合。数据中保留了某条关系，不表示它必然进入每次查询的可见结果。

## RTENLX02 二进制契约

输出为 `english-lexicon-v2.bin` 和 schema **2** 的 `english-lexicon-v2.json`；源 `SOURCES.json` 自己的 schema 仍为 1。所有整数为小端 `u32`，字符串为 UTF-8；字符串引用是相对末尾字符串区的 `offset,length` 两个整数。

文件顺序：`HEADER → WORD[] → KEY[] → REL[] → 字符串区`。

| 记录 | 字节 | 字段及记录内偏移 |
| --- | --- | --- |
| HEADER | 24 | `RTENLX02`：0–7；英文词数：8；拼音键数：12；关系数：16；字符串区字节数：20 |
| WORD | 36 | 英文词引用：0；词性：8；中文释义：16；音标：24；英文 rank：32 |
| KEY | 16 | 拼音键引用：0；首个关系索引：8；关系数：12 |
| REL | 40 | 英文 WORD ID：0；中文词项引用：4；数字声调读音引用：12；原义项引用：20；中文词频：28；来源／用法 flags：32；原义项序号：36 |

`flags` 为可组合位：`1`＝规范化 CC-CEDICT 英文义项，`2`＝ECDICT 精确中文释义反向关联，`4`＝旧／文言义，`8`＝专名、姓氏或异体提示。关系必须至少有 `1/2` 中的一位，未知位拒绝；双来源佐证可同时有 `1|2`。同一关系只合并来源位，保留最佳义项自己的用法位和原义项序号，不能把另一古义的标签混入现代义。

文件由资源 worker 校验并映射为只读数据，字符串借用不可变文件映射，发布为共享快照；失败不得把损坏文件当作有效词典。安装包同时校验清单、字节数与 SHA256，并带完整 `LICENSE-Wanxiang`。该关系表替代 v1 的裸英文 ID 列表，不能仅改 magic 后继续读取旧记录布局。

## 查询索引、上限与展示

实现见 [lexicon.rs](../../core/english/src/lexicon.rs)。当前源码在 worker 的加载／校验阶段汇总每个拼音键的最佳“现代层级、中文频率”，构建只读优先级数组和区间最大值树；前缀查询用堆选择键，不在按键线程重建索引或遍历整个键表。相应预算与排序回归已随本版正式构建通过，不能由此推及所有长尾翻译质量。

- **精确键**：保持编译后的关系次序，最多检查 512 条关系（重复关系也消耗预算），按英文词去重并返回最多 64 个结果；不再按英文 rank 重排。
- **前缀扩展**：非精确输入至少 3 个字母，通过索引选最多 64 个键；每键最多检查首 64 条关系，总关系预算仍为 512，最终最多 64 个不同英文词，保留最佳中文证据。现代层级和中文频率优先，之后才考虑少补字母及稳定次序。
- Windows 主补词通道请求最多 **24** 个候选，异步拼写可追加至内核 **32** 项，每页最多 5 条。罕见词或后面的义项可能超过查询预算或 UI 上限；不承诺所有已收录关系都能列出，也不承诺固定排名。
- `EnglishAnnotation` 的 `matched_chinese`、`matched_pinyin`、`pinyin_exact` 仅供来源展示。界面用“拼音 · 想”与“扩展 · 想法”区分精确／扩展，标签有长度和行宽上限；中文、声调读音及标签都不进入英文正文。

## 原串确认与混合尾词

自动空格开启时，未明确选择候选的 Space 只对已输入字母做保守原串分隔；出现拼音解释时保持原串，避免把拼音字母偶然拆成英文词，不翻译、不自动补尾空格。关闭时仍可按物理 Space 输入手动空格。组字中的 Enter 始终确认原串并吃键，不接受候选、不分词、不触发宿主提交；无组字时由应用处理。

显式选词是另一条路径：`iwilldotheyiyang`／`iwilldothetongyang` 可提供展示为 `same`、完整提交为 `I will do the same` 的候选，标题显示英文前缀和原始拼音尾部。数字、Tab、点击或明确选择后 Space 确认时，应整段替换一次，不能重复拼接前缀。混合查询受拼音和连写开关共同控制；它不改变原串分词的字符保真规则。

## 现代实体是独立的小目录

[审核 JSON](../../data/dict/modern-entities.json) 当前有 51 条公司、产品和开发工具名称，生成独立的 [EAMODEN1 TSV](../../data/dict/modern-entities.tsv)，作为有限候选流嵌入程序。它不是完整现代实体库，不能替代普通英文释义；如实体 `Anthropic` 与普通 `anthropic` 的形容词义需要保留各自身份。

每条记录保存 Wikidata QID、固定修订版与官方站链接，结构化来源为 CC0；官网链接用于身份核对，不表示复制其网页正文或将官网素材改标 CC0。`entity_kind/source` 与拼音证据分开，界面可标“现代 · 公司／产品”。实际条数、审核 JSON、TSV 和冻结快照摘要写入 `build.json.ModernEntities`，不增加单独的运行时数据文件。

维护使用 `modern-entities.py --propose-refresh <单独提案路径>` 产生独立审阅材料；审查身份、中文说明和来源后才更新审核 JSON，再显式 `--write-runtime` 并 `--check`。提案不能覆盖已审核文件，正常输入及正常构建不在线抓取新实体。核心补词／查词不逐键联网、不自动学习输入历史；AI 仅走用户明确调用的独立功能。

## 审核与可复现交付

1. 修改前审查原文版本、许可和哈希；数据或规则变更应配离线 fixture，覆盖常用／旧义、多音、精确／扩展、预算、标签和混合完整提交。
2. 使用明确的 Python 3.11+ 运行 `test-build-lexicon.py`、`test-prepare-lexicon.py`、`test-modern-entities.py`，并执行 `modern-entities.py --check`。这些工具位于 `tools/english-assist/`；安装消费端另有纯 PowerShell 格式、哈希和冻结清单测试。
3. 普通 `prepare-lexicon.py --output dist/english-dictionaries` 校验冻结输入、重新编译，并与[审核输出清单](../../data/dict/english-lexicon.json) 完整比较。差异必须失败；`--verify-only` 只核对已有产物，不等于重编译证明。
4. 只有已审阅的数据／编译规则变更，才显式运行 `prepare-lexicon.py --output dist/english-dictionaries --refresh-manifest`，检查新摘要、数量和实际映射差异。不得把自动刷新当作失败后的兜底。
5. 源码 ZIP 应包含原始压缩数据、万象选定源文件、完整许可／NOTICE、实体审核 JSON／TSV／快照、英文词频／双词资源、编译器、测试及输出清单。保持固定换行／二进制属性，避免归档改变已审核字节。
6. 从最终提交的源码 ZIP 隔离解压，**不带 `--refresh-manifest`** 重建并核对输出；再按正式流程冻结生产 DLL/EXE 后运行测试、打包和核对安装产物。源码可重建、单元测试、安装探针与真实应用验收应分别记录，不互相替代。
