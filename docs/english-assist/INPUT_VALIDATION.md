## 3. 关键代码审查发现

### 已修复，等待运行验证

1. 英文模式的数字 1–8 原来用于选词；已改为统一原样输入。TSF 同一编辑事务
   先提交原组合，再插入数字，避免异步提交落到数字后面。
2. Tab 和点击原来自动附加空格；已改为不附加，空格键仍有明确的加空格语义。
3. 显式 Enter 原来仍放行给宿主；现在仅在显式选择有效时消费，第二次才放行。
4. 原生候选去掉数字后，UI-less 接口仍宣称显示数字；两处已同步。
5. 候选位图缓存原来没有单独记录显示数字的模式；已增加模式字段，避免内容
   与选择相同但模式变化时错误复用。
6. TSF 激活时若系统暂未报告当前 Profile，原先回退中文；英文专用分支改为
   回退英文，避免进入没有中文词库的模式。
7. 上游“中文词库未加载则原样输入”的限制原本会阻断英文；现在只对中文模式生效。
8. 英文提交原来会自动学习词汇；当前分支不再发出英文提交的学习副作用。
9. 旧文档的数字选词、尾空格和中英文双入口说明已换成本分支实际约定，并标明未测。

### 静态核对结果与剩余边界

- 只注册 en-US Profile，COM CLSID 和英语 Profile GUID 与上游不同；需要在
  真正的语言列表和实际激活中验证，不能只看常量。
- 专用构建脚本为 platforms/windows/installer/build-english-assist.ps1，
  安装器为同目录 english-assist.iss。继承的上游安装路线不能用于本分支。
- 英文 image 设计为安装到版本目录的 dictionaries/，用户级
  BaseDictionaryRoot 指向该只读目录；其路径与 x86/x64 AppContainer 访问仍需实测。
- 英文资源由后台激活；核心在新组合开始时获取当前 vocabulary。
  应验证“词库尚未加载时敲字”以及“加载后下一词能补全”，不能只在热态测试。
- 源码仍保留上游其他平台和中文模块，当前不会作为系统中文 Profile 安装。
- 字符最小触发数、手动个人词库、应用直输列表、主题和完整现代候选布局属于后续工作。
- AI 选区、服务、预览属于其他模块的开发范围。没有真实服务和宿主验收前，
  不能把“有 API 返回字符串”写作“语法修正已可用”。

## 4. 工具链就绪后的执行顺序

~~~powershell
cargo fmt --all -- --check
cargo test --locked -p retype-engine --test english
cargo test --locked -p retype-candidate-ui --features egui --lib
cargo test --locked -p retype-tsf
cargo test --locked --target i686-pc-windows-msvc -p retype-tsf
.\platforms\windows\installer\build-english-assist.ps1 -Installer
~~~

每条命令记录退出码、源码版本、Rust/工具链版本和失败原因。单独执行格式检查时
必须读取它自己的退出码，不能使用最后一条 PowerShell 命令的成功掩盖前面的失败。
默认构建脚本不跳过其配置的测试；NoTest 产物不能作为通过验收的发布包。

不执行继承的 register.ps1 进行临时目录注册，也不使用上游 Retype 安装包证明本分支功能。
